🎯 Go vs Node.js Backend Interview Mastery

The most frequent and critical interview questions asked by senior engineering teams when evaluating developers transitioning from Node.js/TypeScript to Go.

📊 Architectural Mental Model: Node.js Event Loop vs Go M:N Scheduler
How concurrency actually executes under the hood in both runtimes:
Node.js mental model: Single-threaded JavaScript execution engine with an asynchronous event loop. Good for I/O bound tasks; fatal for CPU-heavy tasks without Worker Threads.

Go Architecture: Go uses the M:N Scheduler (M OS threads multiplexed across N Goroutines via P logical processors). Goroutines start with only 2 KB of stack space (compared to 1-2 MB for OS threads or Node Worker threads) and grow dynamically.

Go supports true hardware parallelism across all CPU cores automatically. If a Goroutine blocks on a network syscall or channel, the Go runtime detaches the OS thread and runs another Goroutine instantly (cooperative and preemptive work-stealing).

Interview Pro-Tip: Mention that since Go 1.14, Go has asynchronous preemption using OS signals (SIGURG). Even a tight infinite loop (for {}) without function calls will NOT lock up a CPU core indefinitely.

Node.js mental model: In JS, if val === null, then Boolean(val) is always false. In Go, an interface can hold a nil pointer and yet interface != nil evaluates to true!

An interface value in Go is represented under the hood as a two-word tuple: (type, value).

  • An interface is only equal to nil if both its type and its value are nil.
  • If you return a typed pointer that happens to be nil (e.g. var err *MyCustomError = nil) as an error interface, the interface's type is *MyCustomError, so err != nil is TRUE!
func GetUser() error {
    var customErr *NotFoundError = nil
    return customErr // BUG: returns interface(*NotFoundError, nil)
}

func main() {
    if err := GetUser(); err != nil {
        // THIS CODE RUNS even though customErr was nil!
        fmt.Println("Error occurred!")
    }
}
Interview Pro-Tip: Always return explicit nil rather than a typed nil pointer when implementing error returns: return nil.
Node.js mental model: JS only has Array, which is an auto-resizing dynamic object on the V8 heap.

In Go:

  • Array ([5]int): Fixed size, part of the type signature. Passed entirely by value (copies all elements when passed to a function).
  • Slice ([]int): A lightweight 24-byte header containing:
    1. Data uintptr (pointer to the underlying array)
    2. Len int (number of accessible elements)
    3. Cap int (total capacity of underlying buffer)

Growth Algorithm: When appending beyond capacity, Go doubles capacity up to 256 elements; beyond 256, it transitions smoothly to growing by ~25% to minimize memory waste.

V8 (Node.js): Uses a Generational Garbage Collector (Scavenger for young generation + Mark-Sweep-Compact for old generation). Optimized for dynamic scripting languages where millions of short-lived objects are born in functions. Can experience stop-the-world pauses under heavy memory churn.

Go Runtime: Uses a Concurrent Tri-Color Mark-and-Sweep Garbage Collector without generational collection or object moving/compaction.

  • Sub-millisecond latency: Go prioritizes predictable low latency over absolute throughput. GC pauses are typically < 0.5 ms.
  • Escape Analysis: Because Go puts the vast majority of local variables and small structs on the stack, they are freed instantly upon function return without GC involvement!
  • Tuning: Controlled primarily by GOGC (default 100% target ratio) and GOMEMLIMIT (Go 1.19+ soft memory ceiling to prevent OOM kills in Docker/Kubernetes).

Escape Analysis is the Go compiler's static analysis step that determines whether a variable can be safely allocated on the fast Stack or must "escape" to the Heap.

  • Stack allocation: Ultra-fast (moving stack pointer), zero GC overhead.
  • Heap allocation: Requires runtime memory allocator and GC tracing.

Common reasons variables escape to heap:

  1. Returning a pointer to a local variable from a function.
  2. Passing values into interface parameters (e.g., fmt.Println(x) takes ...any, forcing x to escape).
  3. Allocating slices with dynamic sizes that cannot be resolved at compile time.
Interview Pro-Tip: You can inspect the compiler's escape analysis decisions in terminal via: go build -gcflags="-m -m".

A Goroutine leak occurs when a Goroutine is spawned but remains blocked forever (waiting on a channel that is never written to, or reading from a socket without a timeout). Because Goroutines are never garbage-collected while alive, memory grows monotonically until the pod OOM crashes.

Prevention Strategies:

  • Always pass a cancellable context.Context to long-running or async goroutines.
  • Use buffered channels when you know the number of workers, or use a select with ctx.Done().
  • Monitor total goroutine count in Prometheus using runtime.NumGoroutine().
  • Attach net/http/pprof to inspect live goroutine stack dumps via /debug/pprof/goroutine?debug=1.
