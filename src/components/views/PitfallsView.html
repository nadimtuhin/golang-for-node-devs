⚠️ Known Pitfalls & Footguns (For Node.js Devs)

Common traps where JavaScript intuition leads to silent bugs, race conditions, memory leaks, or unrecoverable panics in Go.

📐 Memory Footprint: JS Object Graph vs Go Contiguous Memory Layout
Why Go structs take 10x less RAM and produce zero garbage collector pointer fragmentation:
🪤 Pitfall 1: Loop Variable Capture in Goroutines (Pre-Go 1.22)

In Go < 1.22, closures inside goroutines captured the memory address of the shared loop variable! While Go 1.22+ officially fixed this by scoping variables per-iteration, passing arguments explicitly remains the universal best practice for backward compatibility.

❌ BUGGY: All goroutines print the LAST item
items := []string{"a", "b", "c"} for _, v := range items { go func() { fmt.Println(v) // Captures single pointer! }() } // Outputs: "c", "c", "c"
✅ FIX: Pass variable as explicit argument
items := []string{"a", "b", "c"} for _, v := range items { go func(val string) { fmt.Println(val) // Copied by value! }(v) } // Outputs: "a", "b", "c" (unordered)
🪤 Pitfall 2: Sub-Slicing Retaining Giant Underlying Array

Sub-slicing shares the original array. If you slice 5 bytes from a 50MB file buffer and keep the slice, the entire 50MB array cannot be garbage collected!

❌ BUGGY: Retains 50 MB in RAM forever
func getHeader() []byte { bigFile := read50MBFile() // 50MB buffer return bigFile[:10] // Pointer to 50MB! }
✅ FIX: Copy into newly allocated slice
func getHeader() []byte { bigFile := read50MBFile() header := make([]byte, 10) copy(header, bigFile[:10]) // Independent array! return header // bigFile is garbage collected }
🪤 Pitfall 3: Concurrent Map Mutation Crashes the Process

In JS, single-threading prevents race condition panics. In Go, multiple goroutines writing/reading a map concurrently will throw fatal error: concurrent map read and map write which CANNOT be caught by recover()!

❌ BUGGY: Fatal unrecoverable process crash
m := make(map[string]int) go func() { m["a"] = 1 }() go func() { _ = m["a"] }() // CRASH: fatal error: concurrent map access
✅ FIX: Protect with sync.RWMutex
type SafeMap struct { sync.RWMutex data map[string]int } // Read: mu.RLock(); val := data[k]; mu.RUnlock() // Write: mu.Lock(); data[k] = v; mu.Unlock()
🪤 Pitfall 4: Defer inside Long Loops Leaks File Descriptors

defer does NOT run at the end of a loop iteration; it runs when the surrounding function returns! Putting defer inside a loop of 10,000 files will keep all 10,000 file descriptors open simultaneously.

❌ BUGGY: "too many open files" OS crash
for _, filename := range files { f, _ := os.Open(filename) defer f.Close() // Will NOT close until main() ends! }
✅ FIX: Wrap in helper function or close manually
for _, filename := range files { func(name string) { f, _ := os.Open(name) defer f.Close() // Closes when this anonymous func exits! }(filename) }
🪤 Pitfall 5: Accidental Variable Shadowing with :=

Using := inside an if block creates a new block-scoped variable, shadowing the outer variable and leaving it unchanged.

❌ BUGGY: client remains nil outside if block
var client *HttpClient if env == "prod" { client, err := NewProdClient() // SHADOWS client! if err != nil { return err } } // client is still nil here!
✅ FIX: Declare err separately, use = for client
var client *HttpClient var err error if env == "prod" { client, err = NewProdClient() // Assigns to outer client if err != nil { return err } }
🪤 Pitfall 6: Lowercase (Unexported) Fields Silent JSON Null

In Go, lowercase struct fields are package-private. The encoding/json package is in another package, so it cannot see unexported fields and silently ignores them!

❌ BUGGY: Serializes to empty "{}"
type User struct { name string // Lowercase: Unexported! email string // Lowercase: Unexported! } bytes, _ := json.Marshal(User{"Tom", "t@t.com"}) // Result: "{}"
✅ FIX: Capitalize fields and use struct tags
type User struct { Name string `json:"name"` Email string `json:"email"` } bytes, _ := json.Marshal(User{"Tom", "t@t.com"}) // Result: '{"name":"Tom","email":"t@t.com"}'
🪤 Pitfall 7: The Nil Interface Trap (Typed nil != nil)

An interface in Go consists of two 8-byte words: (type, value). An interface is only equal to nil if BOTH its type and value are nil. Returning a typed nil pointer satisfies the interface but makes err != nil evaluate to true!

❌ BUGGY: err != nil triggers even though pointer is nil!
type CustomErr struct{} func (e *CustomErr) Error() string { return "custom fail" } func Validate() error { var err *CustomErr = nil return err // Returns interface: (Type: *CustomErr, Value: nil) } if Validate() != nil { // 💥 TRIGGERS! The interface holds a concrete type! }
✅ FIX: Return untyped nil explicitly
type CustomErr struct{} func (e *CustomErr) Error() string { return "custom fail" } func Validate() error { // Return untyped nil directly on success return nil // Returns interface: (Type: nil, Value: nil) } if Validate() != nil { // ✓ Evaluates to false as expected! }
🪤 Pitfall 8: Unclosed HTTP resp.Body Leaks TCP Sockets

In Node.js, fetch/axios automatically cleans up socket connections. In Go, failing to close resp.Body prevents TCP connection reuse, causing connection exhaustion under load. Also, calling defer resp.Body.Close() BEFORE checking err != nil will panic!

❌ BUGGY: Nil panic on error + TCP connection leak
resp, err := http.Get("https://api.com") defer resp.Body.Close() // 💥 PANIC if err != nil! if err != nil { return err } body, _ := io.ReadAll(resp.Body)
✅ FIX: Check error first, defer close, drain body
resp, err := http.Get("https://api.com") if err != nil { return err } defer resp.Body.Close() _, _ = io.Copy(io.Discard, resp.Body) // Drain to enable HTTP Keep-Alive reuse
🪤 Pitfall 9: time.After in Loop / Select Leaks Timers

In Go < 1.23, time.After(d) allocates a time.Timer that is NOT garbage collected until duration d elapses. Calling it inside a continuous select loop accumulates thousands of uncollected timers in memory. (Note: Go 1.23+ overhauled the timer runtime so unreferenced timers are immediately garbage collected and channel buffering issues are resolved).

❌ BUGGY: Accumulates thousands of timers in heap
for { select { case msg := <-ch: process(msg) case <-time.After(30 * time.Second): // 💥 Leaks 1 timer per loop iteration! handleTimeout() } }
✅ FIX: Reuse time.NewTimer (with drain pre-1.23 or native Reset in 1.23+)
// Pre-Go 1.23: Explicitly drain timer.C if Stop() returns false before Reset() timer := time.NewTimer(30 * time.Second) defer timer.Stop() for { select { case msg := <-ch: if !timer.Stop() { select { case <-timer.C: default: } } process(msg) case <-timer.C: handleTimeout() } // In Go 1.23+, timer.Reset(d) safely cleans up expired channels automatically! timer.Reset(30 * time.Second) }
